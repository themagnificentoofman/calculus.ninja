## Authority and withdrawal boundary

D1 authorizes an exact immutable operation against current eligibility. Its successful conditional authorization is the eligibility decision point. A withdrawal committed before it blocks the operation. A later withdrawal preserves that exact authorization, even if Firestore activation has not committed yet. Active games, grades and replays remain immutable. This is an explicit two-commit policy, not a claim that D1 and Firestore form one atomic transaction.

Firestore owns the private intent state and player-visible activation. An orphan authorization never displays questions. Only an exact authorized PREPARED operation may atomically become ISSUED with its game, replay and exposure updates. CANCELLED and EXPIRED are terminal before activation; late D1 responses cannot revive them.

A partially completed change stays disabled. Disable followed by reenable cannot resurrect an old ticket. Readers, graders and recorded replay remain available for already active games. ## Required operation flow

1. Accept an account-scoped stable client operation ID and bind the canonical request, exact selected snapshot and final order. Generate randomness once outside retryable transactions. A changed body under the same ID conflicts.
2. Atomically prepare the private question set and reservation in Firestore against the exact history/generation token. Return only ID/count/status. Identical retries recover the same preparation.
3. At first activation, return an already active exact game first. Otherwise recover an existing exact D1 ticket **before** current eligibility validation; lost acknowledgement must not accidentally revoke an earlier authorization. If none exists, validate current history excluding only this operation's own preparation, the creation-control version, exact saved questions/current source policy, and remaining horizon capacity from a coherent catalog snapshot.
4. Conditionally insert a compact immutable D1 authorization only if catalog epoch, creation gate, registry/policy digest and short authorization deadline still match. Capture epoch with eligible rows in the same SQL snapshot. Every eligibility-affecting mutation must advance it atomically, including composition, withdrawals, approval, supersession, aliases and registry policy.
5. Outside the Firestore callback, obtain the trusted exact receipt. Inside the callback, read all required documents first and compare owner, body, PREPARED state, reservation, current history guard, control version and receipt binding. Create game/replay and promote reservation in the same transaction. No D1 access, decoding or selection occurs inside this retryable callback.
6. Cancel or expire unserved intents transactionally, releasing only their preparation and advancing generation. Preserve terminal identity/body tombstones throughout the supported retry lifetime. Uncertain acknowledgements recover by exact ID without reselection or refreshed exposure.
