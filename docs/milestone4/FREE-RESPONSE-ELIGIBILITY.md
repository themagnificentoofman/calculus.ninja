# Free-response eligibility foundation

Local, unpublished and not connected to round creation. The production registry is empty. This work does not certify any pool, practice horizon or serving selector.

`free-response-eligibility.mjs` translates the compiled exact-record registry into bounded private SQL input. A record must match its task identity, contract identity and record hash, possess the exact current independent-review/checker receipt, have immutable prepared metadata, and have no FR withdrawal. Unsupported or stale registrations cannot contribute to counts. A genuinely original task needs no MC source; an MC conversion retains its exact source release, identity, revision, hash, construction and exposure lineage.

Converted records additionally require approved source publication and current active/composed MC membership. Active-release exclusions, published global exclusions and family withdrawals apply before eligibility. Every returned metadata row is then checked against the compiled `selectionHash`, derived from all its actual task, classification, identity and source fields. This prevents a fabricated first index insertion from changing eligibility or counts without changing an approved record.

Normalization uses two passes to find the latest eligible revision of each task before checking for an ambiguous current grading contract. Topic, difficulty and technique filters apply afterward. An older revision cannot reappear under a superseded classification or lineage; older contracts also cannot make a uniquely revised task fail merely because of insertion order. Distinct tasks with the same exposure lineage may have different genuine classifications. Within the requested pool, retain one representative per exposure lineage. Cross-format history must still suppress that lineage in every pool. If a newer record is unregistered or unsupported, it is outside the eligible inventory rather than an authority to suppress approved content.

The query returns private metadata, not compressed problem payloads or expected answers. Bounds are 6,000 registrations, a 1,500,000-byte registration argument, 256 UTF-8 bytes per metadata string and 1,536 aggregate metadata text bytes per row. SQL returns an explicit rejection flag and null metadata for an oversized row, avoiding materialization of its unbounded values. The initial catalog uses two bind parameters. The selector’s final coherent catalog/history query uses three; both fixed SQL statements fit below D1's documented 2,000,000-byte string limit. These are design bounds, not hosted performance measurements. [Cloudflare D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

`0009_free_response_selection_metadata.sql` is additive and has no activation pointer. The local index operator reconstructs the exact immutable record, reruns its admission evidence, requires its stored receipt, and derives selection metadata from that record. Existing mismatched metadata is rejected. UPDATE, DELETE and REPLACE guards preserve metadata and withdrawals, including with recursive triggers disabled. Nullable source tuples require explicit non-null revision/hash checks when populated: a SQL CHECK evaluating to NULL is not rejection. A withdrawal removes future eligibility while preserving task, contract, receipt and historical data.

Independent v3 passes 122 preserved probes and 12 full revision/contract insertion-order permutations. Earlier failures and exact source bindings remain in the private review packages referenced by `integration-review-index-v3.json`; nine owner test groups pass separately. This evidence covers the bounded foundation only.

The private selector now reconstructs selected payloads, verifies registered hashes and derived metadata, retains randomized history weighting and cross-format lineage, and rechecks eligibility and retained-history aliases together in one SQL statement before returning private records. Two alternating final queries are insufficient: a withdrawal can arrive between them. This is not yet an atomic persisted-round issuance check. It must fail closed on mismatched data and explicit exhaustion. A catalog count is not a demonstrated round or horizon.
